# Иллюстрации ребусов

Свои картинки стоят в ребусе рядом с эмодзи и цветными буквами Nunito Black, на экране телефона
и часто размером с ноготь. По этому гайду художник (или агент) рисует, а дизайнер одобряет.
Картинку, которая нарушает хоть один пункт **чек-листа** ниже, не одобряют.

Связанные документы: замыслы и заглушки — [REBUS-SPEC.md](REBUS-SPEC.md), правила ребусов — [REBUSES.md](REBUSES.md).

## 1. Как картинку видит ребёнок

- Картинка — квадрат со стороной `--e`. Её считает `src/ui/board.js`: от **240 px** (одна картинка
  на экране) до **32 px** (длинный ребус в две строки). В «первых буквах» — `0.8 × --e`,
  в разборе «Как разгадать» — **44 px** (в ландшафте на телефоне — 32 px).
- Фон под картинкой — кремовая доска `#FFFDF8 → #FFF9EF`, в «первых буквах» — `#FFF8E0`
  с жёлтой пунктирной рамкой. Рядом — эмодзи шрифта устройства (Apple, Google, Microsoft — каждый
  в своём стиле) и буквы пяти цветов: `#E8604C`, `#2C88C9`, `#27996C`, `#B87400`, `#8A5FD1`.
- Всё, что про *операции*, рисует приложение, а не художник: запятые, зачёркнутая буква,
  `Р = Н`, цифры над картинкой, значок переворота ↺, рамка «первых букв», белая плашка под картинкой
  внутри буквы. Если в `look` замысла написано «под ним красным зачёркнута буква Р» или «нарисован
  перевёрнутым со значком ↺» — рисуется **только предмет, прямо**.

## 2. Формат файла

| Что | Правило |
|---|---|
| Формат | SVG, только векторные фигуры. Без растра внутри, `<text>`, шрифтов, ссылок на внешние файлы, `<script>`, `<foreignObject>`, CSS-анимаций |
| Холст | `viewBox="0 0 128 128"`, без `width`/`height` (размер задаёт приложение) |
| Безопасное поле | Предмет внутри `8…120` по обеим осям (поля 8 = 6 %). Ничего не обрезается краем |
| Заполнение | Предмет касается безопасного поля с двух противоположных сторон (по ширине или по высоте) — тогда он по «весу» как эмодзи соседнего размера. Узкий предмет (игла, фонарик) — по диагонали, как ✏️ |
| Опора | Нижняя точка предмета — на линии `y = 120`, по центру по горизонтали. Летающее (оса, бабочка) — центр массы чуть выше центра, без опоры |
| Направление | Живое и движущееся смотрит/едет **вправо** (по ходу чтения). Зеркальную копию делает дизайнер отдельным файлом, если ребус требует |
| Фон | Прозрачный. Ни земли, ни неба, ни кружка-подложки |
| Вес | ≤ 8 КБ после оптимизации (SVGO), ≤ 40 фигур |
| Имя | `public/pictures/<слово-латиницей>.svg`: `rak.svg`, `ezh.svg`; вариант — `rak-2.svg` |
| Тень | **Не рисовать.** Приложение даёт картинке ту же тень, что эмодзи: `drop-shadow(0 .015e .03e rgba(90,60,30,.35))` |

## 3. Стиль

Цель — чтобы своя картинка в ряду с 🐘 🐌 🐧 не выглядела чужой ни на Android, ни на iPhone.
Общий знаменатель эмодзи — крупные плоские пятна, мягкие формы, без чёрного контура.

- **Заливка плоская.** Основной цвет + одна тень (тот же оттенок, темнее на ~20 %) + максимум
  один светлый блик. Без градиентов, текстур, штриховки, прозрачности ниже 100 % (кроме луча
  фонарика и подобного «света» — до 60 %).
- **Контур — не чёрный.** Обводка в тон заливки, темнее на ~35 % (рыжий кот — `#B8561F`, не `#000`),
  толщина **4** единицы из 128 (≈ 3 %), `stroke-linejoin="round"`, `stroke-linecap="round"`.
  Контур обязателен у светлых предметов (сыр, вата, игла, облако), чтобы они не растворились
  на кремовом фоне; у ярких — по желанию, но во всём наборе одинаково.
- **Мягкие формы.** Углы скруглены (радиус ≥ 3), как у букв Nunito и карточек приложения.
  Острые углы — только там, где острота и есть признак (игла, плавник окуня, клюв).
- **Самая мелкая деталь — 8 единиц** (на 32 px это 2 px). Глаз — кружок ≥ 8, блик в глазу ≥ 3.
  Всё мельче — убрать.
- **Палитра.** Предметы — в своих природных цветах (лимон жёлтый, лиса рыжая, огурец зелёный),
  насыщенных, но не кислотных. Для «искусственных» предметов без своего цвета (санки, фонарик,
  шатёр) — тёплые тона приложения: `--coral #FF9A88`, `--sun-deep #FFC94D`, `--mint #BFEBD5`,
  `--sky #BFE2F8`, `--lilac #DCCBF7`, тёмные детали — `--ink #3A2E28` (вместо чёрного).
  Чистый `#000` и `#FFF` большими пятнами не использовать: белое — `#FFFDF8` с контуром.
- **Нельзя:** красный `#E5483A` линией поперёк предмета и красные крестики (читаются как
  «зачёркнуто» / «нельзя»); буквы, цифры, надписи, ноты, стрелки на самом предмете; лица у неживых
  предметов («весёлый лимон» — нет, лимон).

## 4. Читаемость

- **Один предмет, самый узнаваемый ракурс.** Ребёнок 5–8 лет называет его тем словом, что в замысле,
  с первого взгляда и без подписи. Животные — целиком, сбоку или в ¾; посуда и инструменты — сбоку.
- **Признак слова виден на 32 px.** Окунь — полоски и колючий плавник, енот — маска,
  хомяк — щёки. Если признак пропадает в маленьком размере, его увеличивают, а не детализируют.
- **Не подсказывает соседнее слово.** Кот не «котёнок» (без бантика и клубка), рот — не «губы»
  и не «улыбка»: признак слова из замысла главный, остальное убрать.
- **Силуэт.** Залитый тёмным, силуэт всё ещё узнаётся. Это главный тест.
- **Переворачиваемые** (в реестре `flip: true`): верх и низ явно разные (у кота уши и лапы),
  вверх ногами предмет остаётся тем же предметом. Симметричные сверху-снизу (мяч, сыр) — `flip: false`.

## 5. Картинка рядом с буквой и с другой картинкой (отношения `rel`)

Общие правила: приложение раскладывает части, художник рисует **каждую картинку отдельным файлом**
по правилам выше (опора на `y = 120`, прозрачный фон) — тогда любые сочетания собираются без перерисовки.
Буква в ребусе всегда остаётся буквой Nunito Black, художник её не рисует.

| Отношение | Как выглядит | Требование к картинке |
|---|---|---|
| **В** — картинка внутри буквы | Буква крупно (`1.15 × --el`), картинка ~40 % высоты буквы на белой скруглённой плашке, как буквы в букве | Компактный силуэт, пропорции ближе к квадрату (не уже 1 : 1.6). Перекрывает не больше трети штрихов буквы — буква должна читаться. Буква внутри картинки (буква в доме) — только если у картинки есть явный «проём»: художник рисует её в два слоя (см. ниже) |
| **НА** — картинка на букве / на картинке | Картинка стоит вплотную на верхнем краю нижнего | У стоящей картинки ровный низ: лапы, дно, полозья. Нижняя картинка — с плоским или широким верхом |
| **НАД** | Как НА, но с зазором | Летающее или висящее; нижний край не должен «тянуться» вниз (нитки, лучи) |
| **ПОД** | Картинка под буквой | Верх без тонких выступов (усики ≤ 8 % высоты), чтобы не слиплись с буквой |
| **У** — маленькое у большого | Картинка ~½ высоты буквы, на одной линии низа, вплотную | Смотрит **на** буквы (по умолчанию вправо; если стоит справа от букв — нужен зеркальный файл) |
| **ЗА** — выглядывает из-за | Заднее сдвинуто вверх и перекрыто передним на 20–40 % | У переднего — сплошной силуэт без дыр и белый ореол (приложение даёт, как у буквы `ЗА`). Узнаваемая часть заднего (голова, верх) остаётся видна |
| **ПЕРЕД** | Наоборот: картинка загораживает | Как ЗА |
| **ИЗ** — выходит, вылетает | Предмет частично внутри другого | Нижняя картинка в два слоя (см. ниже) |
| **ПО** — сложено из маленьких | Много копий `a` выложены формой `b` | `a` узнаётся на 24 px; у такой картинки упрощённый вариант `<слово>-mini.svg` |
| **С, ПРИ, К, ОТ, ДО, О/ОБ** | Рядом, со стрелкой движения или касанием | Отдельных требований нет; стрелки и «бах» рисует приложение |

**Два слоя** (для «в», «из», «за» с проёмом): одна картинка, две группы
`<g id="back">` (задняя стенка, внутренность) и `<g id="front">` (передний край). Приложение
кладёт вложенное между ними. Делается только по заявке разработчика под конкретный ребус.

**Контраст в отношениях.** Цвет буквы заранее не известен (их пять, по очереди). Поэтому картинка,
касающаяся буквы, должна отделяться от **любого** из пяти цветов: работает контур в тон (п. 3)
и белый ореол/плашка от приложения. Картинку целиком одного из этих цветов (сплошь синюю
`#2C88C9`, сплошь фиолетовую) рядом с буквой не делать.

## 6. Тёмная тема

Сейчас у приложения только светлая тема (`theme-color #FFF8EC`, без `prefers-color-scheme`).
Чтобы картинки не перерисовывать, если тёмная появится: цвета задаются прямо в SVG (не `currentColor`),
у светлых предметов есть контур, ни одна часть не держится на «цвете фона» (дырки в сыре — заливка,
а не вырез). Проверка: картинка на `#3A2E28` всё ещё читается.

## 7. Доступность

- Текстовую альтернативу задаёт приложение: `alt` = **слово картинки из реестра** (`кот`, `ёж`,
  с Ё), не ответ ребуса. В самом SVG нет `<title>`/`<desc>` — иначе на компьютере всплывает подсказка.
- Смысл не держится только на цвете: «красный рак» узнаётся и в оттенках серого.
- Ничего не мигает и не движется.

## 8. Как картинка проходит путь

1. **Заглушка.** Автор в `data/proposals/*.json` пишет `pic` + `look`. `npm run proposals` в конце
   печатает список картинок для дизайнера. Дизайнер решает: подходит эмодзи из реестра или нужна своя.
2. **Эскиз.** Художник рисует SVG по п. 2–5, кладёт в `public/pictures/`. В реестр
   `data/pictures.json` добавляется запись **без** `designApproved` — сборка (`npm run build`)
   её не пропустит, это нормально: эскиз ещё не в наборе.
3. **Проверка на телефоне.** `npm run dev`, телефон или эмуляция 390×844 и 360×740: картинка
   в ребусе из замысла, в размерах 240, 136, 89, 44 и 32 px, рядом с эмодзи и цветными буквами,
   в нужном отношении. Плюс тест силуэта и тест «вверх ногами» для `flip: true`.
4. **Одобрение.** Дизайнер проходит чек-лист и ставит в запись реестра:

```json
{
  "image": "pictures/rak.svg",
  "word": "РАК",
  "minLevel": 1,
  "flip": false,
  "initials": true,
  "designApproved": true,
  "note": "одобрено дизайнером 2026-11-02: смотрит вправо, есть rak-mirror.svg"
}
```

`designApproved: true` ставит **только дизайнер**. Любое изменение файла картинки снимает одобрение:
поле убирают и проходят шаги 3–4 заново. Авторство и лицензию (своё / CC0 / Apache 2.0) дописывают
в `public/licenses.txt`.

## Чек-лист одобрения

- [ ] SVG, `viewBox 0 0 128 128`, без растра, текста, скриптов, внешних ссылок; ≤ 8 КБ
- [ ] Прозрачный фон, предмет в поле 8…120, касается его с двух сторон, стоит на `y = 120`
- [ ] Своей тени в файле нет
- [ ] Плоская заливка: цвет + тень + блик; контур в тон, 4 единицы, скруглённый; без чёрного
- [ ] Цвета природные или из токенов приложения; нет красных черт/крестиков
- [ ] Один предмет, без фона, надписей, цифр, лиц у неживого
- [ ] Ребёнок назовёт его словом из замысла; ничего не подсказывает соседнее слово
- [ ] Узнаётся на 32 px и силуэтом; мелких деталей < 8 единиц нет
- [ ] В ряду с эмодзи (Android и iPhone) не выглядит чужим
- [ ] В нужном отношении (в, на, под, у, за…) буква читается, картинка отделена от любого из 5 цветов букв
- [ ] Для `flip: true` — узнаётся вверх ногами
- [ ] Читается на тёмном `#3A2E28`
- [ ] Запись в реестре: `image`, `word`, `designApproved: true`, `note`; строка в `licenses.txt`
