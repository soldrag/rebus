# Схема замысла ребуса

Автор ребусов придумывает **замысел**: из чего складывается слово и что где нарисовано.
Он не думает об эмодзи и о том, умеет ли приложение такое рисовать. Картинка в замысле —
это слово и описание, как она выглядит (заглушка). Нарисовать (эмодзи, своя картинка, SVG)
и перенести в `public/data/rebuses.json` — дело дизайнера и разработчика.

Автора ограничивают только правила ребусов в [REBUSES.md](REBUSES.md): возраст 5–8 лет,
ребёнок назовёт картинку именно этим словом, Ё/Е, подсказки, уровни, разнообразие, без повторов.
Пункты REBUSES.md про реестр эмодзи и «что умеет отрисовка» к замыслам не относятся.

Файлы: `data/proposals/*.json`, проверка — `npm run proposals` (решаемость, Ё/Е, повторы с набором,
разметка приёмов; в конце — список картинок для дизайнера).

## Файл

```json
{
  "proposals": [
    {
      "id": "vorota",
      "answer": "ВОРОТА",
      "level": 2,
      "theme": "дом",
      "hint": "Через них въезжают во двор",
      "idea": "Внутри большой буквы О нарисован рот: «В О РОТ», и ещё буква А — ВОРОТА.",
      "techniques": ["pic-in-rel", "rel:В"],
      "parts": [
        { "rel": "В", "a": { "pic": "РОТ", "look": "открытый улыбающийся рот с губами" },
          "b": { "letters": "О" }, "read": ["rel", "b", "a"] },
        { "letters": "А" }
      ]
    }
  ]
}
```

- `idea` — как ребёнок рассуждает, разгадывая (для редактора и дизайнера).
- `theme` — как в REBUSES.md. `techniques` — список приёмов, его сверяет проверка.

## Узлы

Каждая часть — ровно один из видов. Части читаются слева направо.

| Узел | Что это | Буквы |
|---|---|---|
| `{ "letters": "КА" }` | написанные буквы | КА |
| `{ "pic": "КОТ", "look": "рыжий кот сидит" }` | картинка (заглушка) | КОТ |
| `{ "number": "100", "word": "СТО" }` | число | СТО |
| `{ "initials": [{ "pic": "…", "look": "…" }, …] }` | первые буквы картинок | первые буквы |
| `{ "rel": "В", "a": узел, "b": узел, "read": [...] }` | одно относительно другого | по `read` |
| `{ "seq": [узел, …] }` | несколько узлов подряд (например, внутри `rel`) | подряд |

**Операции** у `pic` и `number` (порядок применения: flip → replace → replaceAt → remove → pick → cut):
`cutStart`/`cutEnd` — запятые, `remove: ["Т"]` — зачёркнутая буква, `replace: [["Р","Н"]]` — Р=Н,
`replaceAt: [[2,"О"]]` — 2=О, `pick: [1,2,3]` — цифры над картинкой, `flip: true` — вверх ногами.

**Отношения `rel`** (a — что ставим, b — относительно чего), `read` — порядок чтения из `"rel"`, `"a"`, `"b"`:

| rel | Как нарисовано | Пример |
|---|---|---|
| В | a внутри b | РОТ в О: `["rel","b","a"]` → В-О-РОТ |
| НА | a стоит на b | |
| НАД | a над b с зазором | |
| ПОД | a под b | |
| У | a маленькое вплотную у b | З у Б: `["a","rel","b"]` → З-У-Б |
| ЗА | a выглядывает из-за b | |
| ПЕРЕД | a перед b, загораживает | |
| ИЗ | a выходит, вылетает из b | |
| ПО | b сложено из маленьких a | |
| К, ОТ, ДО | a движется к b / от b / доходит до b | |
| С, ПРИ | a вместе с b / прикреплено к b | |
| О, ОБ | a ударяется о b | |

`a` и `b` — любые узлы: буквы, картинки, числа, даже другой `rel`. Можно предложить новое
отношение или вид узла — тогда опишите его в отчёте, разработчик добавит в схему (`tools/rebus-spec.mjs`).

## Приёмы (`techniques`)

Те же коды, что в приложении (`comma`, `remove`, `replace`, `replaceAt`, `pick`, `flip`, `initials`,
`number`, `plain`), плюс `rel:<предлог>` для каждого отношения и `pic-in-rel`, если в отношении есть картинка.
Список по алфавиту, проверка подскажет правильный.
