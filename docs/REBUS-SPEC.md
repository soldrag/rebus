# Схема замысла ребуса

Автор ребусов придумывает **замысел**: из чего складывается слово и что где нарисовано.
Он не думает об эмодзи и о том, умеет ли приложение такое рисовать. Картинка в замысле —
это слово и описание, как она выглядит (заглушка). Нарисовать (эмодзи, своя картинка, SVG)
и перенести в `public/data/rebuses.json` — дело дизайнера и разработчика. Каждую иллюстрацию
одобряет дизайнер, она соблюдает стиль приложения ([ILLUSTRATIONS.md](ILLUSTRATIONS.md)).

Автора ограничивают только правила ребусов в [REBUSES.md](REBUSES.md): возраст 5–8 лет,
ребёнок назовёт картинку именно этим словом, Ё/Е, подсказки, уровни, разнообразие, без повторов.
Пункты REBUSES.md про реестр эмодзи и «что умеет отрисовка» к замыслам не относятся.

Файлы: `data/proposals/*.json`, проверка — `npm run proposals` (решаемость, Ё/Е, повторы с набором,
разметка приёмов; в конце — список картинок для дизайнера).

## Файл

```json
{
  "proposals": [
    {
      "id": "vorota",
      "answer": "ВОРОТА",
      "level": 2,
      "theme": "дом",
      "hint": "Через них въезжают во двор",
      "idea": "Внутри большой буквы О нарисован рот: «В О РОТ», и ещё буква А — ВОРОТА.",
      "techniques": ["pic-in-rel", "rel:В"],
      "parts": [
        { "rel": "В", "a": { "pic": "РОТ", "look": "открытый улыбающийся рот с губами" },
          "b": { "letters": "О" }, "read": ["rel", "b", "a"] },
        { "letters": "А" }
      ]
    }
  ]
}
```

- `idea` — как ребёнок рассуждает, разгадывая (для редактора и дизайнера).
- `look` — только сам предмет: один, без фона и соседей. Операции (зачёркивание, «2 = О», переворот), буквы и цифры в `look` не пишем — их рисует приложение. Проверка это ловит.
- `exceptions` — необязательно: `{ "<правило>": "почему здесь можно" }` для отступлений от «обычно»-правил (REBUSES.md, «Как устроены правила»).
- `theme` — как в REBUSES.md. `techniques` — список приёмов, его сверяет проверка.

## Узлы

Каждая часть — ровно один из видов. Части читаются слева направо.

| Узел | Что это | Буквы |
|---|---|---|
| `{ "letters": "КА" }` | написанные буквы | КА |
| `{ "pic": "КОТ", "look": "рыжий кот сидит" }` | картинка (заглушка) | КОТ |
| `{ "number": "100", "word": "СТО" }` | число | СТО |
| `{ "initials": [{ "pic": "…", "look": "…" }, …] }` | первые буквы картинок | первые буквы |
| `{ "rel": "В", "a": узел, "b": узел, "read": [...] }` | одно относительно другого | по `read` |
| `{ "seq": [узел, …] }` | несколько узлов подряд (например, внутри `rel`) | подряд |

**Операции** у `pic` и `number` (порядок применения: flip → replace → replaceAt → remove → pick → cut):
`cutStart`/`cutEnd` — запятые, `remove: ["Т"]` — зачёркнутая буква, `replace: [["Р","Н"]]` — Р=Н,
`replaceAt: [[2,"О"]]` — 2=О, `pick: [1,2,3]` — цифры над картинкой, `flip: true` — вверх ногами.

**Отношения `rel`** (a — что ставим, b — относительно чего). Только те, что приложение рисует
(лист дизайнера, [VISUAL-LANGUAGE.md](VISUAL-LANGUAGE.md)). Ребёнок называет, что видит, фразой
с предлогом; части читаются как книга — сверху вниз, слева направо. Поэтому `read` бывает двух видов:
`["a","rel","b"]` — предлог **между** частями, `["rel","b","a"]` — предлог **в начале**, потом левая
(верхняя) часть.

| rel | Как нарисовано | Где предлог | Пример |
|---|---|---|---|
| В | a внутри контура b | как удобнее | РОТ в О: `["rel","b","a"]` → В-О-РОТ |
| НА | a стоит на b вплотную | как удобнее | КА на ВА: `["a","rel","b"]` → КА-НА-ВА |
| ПОД | a под b вплотную | в начале | под К — ОВА: `["rel","b","a"]` → ПОД-К-ОВА |
| У | a маленькое, вплотную слева от b | между | З у Б: `["a","rel","b"]` → З-У-Б |
| ЗА | a выглядывает из-за b: a сзади контуром, b спереди слева | в начале | за К — АТ: `["rel","b","a"]` → ЗА-К-АТ |
| ПЕРЕД | a стоит перед b: b сзади контуром слева, a спереди справа закрывает его угол | в начале | перед А — Й: `["rel","b","a"]` → ПЕРЕД-А-Й |
| ИЗ | a выходит из b: b большой контур, a наполовину снаружи, стрелка от a | в начале | из Ю — М: `["rel","b","a"]` → ИЗ-Ю-М |
| К | a движется к b: a слева, стрелка, b | между | ЧАЙ к А: `["a","rel","b"]` → ЧАЙ-К-А |
| ОТ | a уходит от b: b слева, a, стрелка от b | в начале | от Е — Ц: `["rel","b","a"]` → ОТ-Е-Ц |
| ДО | a доходит до b: линия от a упирается чертой в b | между | ЛА до ШКА: `["a","rel","b"]` → ЛА-ДО-ШКА |

У «ЗА» и «ПЕРЕД» правило одно: предлог в начало, потом **левая** часть (у ЗА левая — переднее, у ПЕРЕД — заднее).
Другой `read` проверка не пропустит («К» читается между частями: read ["a","rel","b"]).

**Не рисуем:** НАД, ПО (слишком сложно и неочевидно для детей), С, ПРИ, О, ОБ. Замысел с ними получает
ошибку `rel «НАД» не рисуем: …` с причиной (реестр `NOT_DRAWN` в `tools/rebus-spec.mjs`, причины —
[VISUAL-LANGUAGE.md](VISUAL-LANGUAGE.md#не-рисуем)).

`a` и `b` — любые узлы: буквы, картинки, числа, даже другой `rel`. Одно исключение: у **«В»** и **«ИЗ»**
`b` рисуется **контуром**, который вмещает `a`, а картинку (и первые буквы) контуром не нарисовать —
там `b` только буквы, проверка ответит `b у «из» рисуется контуром — только буквы`. В остальных
отношениях картинка в `b` стоит как обычная картинка, сплошной: «БУ к ЧАШКЕ без Ч» —
`{ "rel": "К", "a": { "letters": "БУ" }, "b": { "pic": "ЧАШКА", "look": "…", "remove": ["Ч"] }, "read": ["a","rel","b"] }`.
У «ЗА» и «ПЕРЕД» контуром рисуется заднее — картинка там просто стоит сзади, под передним.

## Приёмы (`techniques`)

Те же коды, что в приложении (`comma`, `remove`, `replace`, `replaceAt`, `pick`, `flip`, `initials`,
`number`, `plain`), плюс `rel:<предлог>` для каждого отношения и `pic-in-rel`, если в отношении есть картинка.
Список по алфавиту, проверка подскажет правильный.

## Расширение схемы

Схема открыта: виды узлов (`NODE_KINDS`), операции (`OPS`) и отношения (`RELATIONS`, где читается
предлог — `RELATION_READ`, что не рисуем — `NOT_DRAWN`) — реестры в `tools/rebus-spec.mjs`. Новый приём добавляется новой записью, старое не трогается.

- **Только добавлять.** Новые виды, операции, отношения и необязательные поля. Смысл и порядок
  существующих не меняются; новое поле, если его нет, ведёт себя как раньше.
  Единственное исключение — решение владельца убрать НАД, ПО, С, ПРИ, О, ОБ (их не рисуем):
  ни один образец и ни один замысел их не использовал, теперь они дают ошибку «не рисуем».
- **Образцы.** `tools/spec-fixtures.json` — по образцу на каждый вид, операцию и отношение;
  `npm run proposals` проверяет, что все они решаются как раньше. Расширил схему — добавь образец,
  старые образцы не менять.
- **Новый вид от автора.** Автор может записать замысел с видом, которого схема ещё не знает:
  `{ "kind": "mirror", ... }` (поле `kind` явно называет вид). Проверка не падает, а пишет
  «ждут обработчика»; разработчик добавляет вид в реестр — и замысел начинает проверяться.
  `kind` можно указывать и у известных видов; без него вид узнаётся по единственному ключу.
- **Версия.** У замысла может быть `"schema": 1`. Проверка ругается только на версию новее своей.
- **Приложение.** Ребус с незнакомым приложению видом части не ломает приложение: при загрузке
  такие ребусы пропускаются (`src/data.js` → `formatProblems`), остальные работают. Поэтому
  данные можно расширять раньше, чем все установленные копии приложения обновятся.

## Дубли

Схема детерминированная, поэтому дубли видны по устройству ребуса, а не по словам.
`npm run proposals` отсеивает:

- **пик частотности слова** — одно слово разными ребусами можно, но частотность считается статистически (набор + замыслы): слово не должно встречаться больше двух средних;
- **ответ — просто картинка** — замысел из одной картинки с тем же словом не ребус;
- **тот же ребус** — совпадают все части (описания картинок `look` не считаются);
- **тот же ход** — один приём над тем же материалом уже есть в наборе или замыслах:
  `КОРОНА 1=В`, `ЖУК в О`, первые буквы тех же картинок. Ответы могут быть разные,
  но идея та же — придумайте другую. Просто та же картинка без операции дублем не считается.

## Что ещё проверяется механически

По выводам редактора (`data/proposals/REVIEW.md`) часть содержательных правил проверяет `npm run proposals`:

- ответ не встраивает другой ответ набора или замыслов (КОСА ← ОСА) — «обычно»-правило `embedded`, отступить можно с причиной в `exceptions`;
- предупреждения: `look` с операциями, буквами или цифрами, ответ начинается со слова картинки (не однокоренное ли — СЛОН → СЛОНЁНОК; буква спереди, Ч + ЁЛКА, — можно), картинкой стоит ответ другого ребуса (зеркальная пара — развести по этапам), `look` с фоном или соседями.

Остальное — существительное ли ответ, назовёт ли ребёнок картинку именно так, однокоренные подсказки,
правильная Ё — проверяет редактор.
